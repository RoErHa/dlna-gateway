Mechanism 01The gateway is not in the audio path

For a UPnP renderer, the gateway sends control messages and then gets out of the way. The renderer fetches the bytes itself, directly from the file server.

This single fact explains a surprising amount: why playback is bit-perfect (nothing can resample what it never touches), why the file server must bind a LAN address the renderer can reach, and why volume is set via the renderer's own hardware rather than by scaling samples.

Browser playback is the opposite shape. iOS refuses cross-origin audio in a PWA, so those bytes must be relayed same-origin through the gateway. One library, two topologies:

Mechanism 02Four surfaces, one library

Every client protocol is a view over the same index. Nothing owns its own copy of the library.

This is why the module count looks large for the amount of behaviour: the families are surfaces, not duplicated logic. Below the index sits a provider seam so the backend itself is swappable.

Enforced, not aspirational

Every module carries a line ceiling in a committed budget file: it may shrink, never grow, and a new module is held to 400 lines from birth. As of v2.1.0 all 89 are within that target and the over-budget list is empty — so the ratchet now behaves as a flat limit without ever having needed a flag day.

InvariantWhat survives a rebuild

Re-indexing wipes and repopulates tracks. Everything a person created must outlive that.

This is the rule most likely to be broken by accident, because the natural instinct is to key user data to a track row. Instead each of these tables is independent of tracks and untouched by clear(udn):

The audiobook position is deliberately server-side and keyed to the book, not to a device or a session. That is what makes a book resume on whichever thing you pick up next — phone, car, or the PWA.

BoundaryWhat the gateway is not

Scope decisions that are settled, not pending.

  • Not a transcoder for audio. Original bytes, always. Video transcodes on demand when a client cannot decode it — that rule is about audio fidelity and does not extend to video.
  • Not a commercial-streaming client. DRM and closed protocols put Spotify, Tidal and friends out of reach; the renderer already speaks them natively, which is the right layer for it.
  • Not multi-user. Single user by design. The Subsonic surface has credentials; the rest of the API does not, and the network is the access control.
  • Not internet-facing. LAN and tailnet only, and since the 2026-08-20 audit that is enforced by the listen addresses rather than assumed — see the companion security audit.
